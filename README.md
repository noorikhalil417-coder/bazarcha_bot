# بازارچه (Bazaarche)

ربات تلگرام بازارچه برای ثبت و بررسی آگهی، جست‌وجوی آگهی‌های نشرشده، مدیریت پایهٔ گروه و پشتیبان‌گیری است. پیام‌ها و رابط ربات به دری افغانستان نوشته شده‌اند. برنامه با Python، `python-telegram-bot` و SQLite کار می‌کند و برای اجرای پیوسته از polling استفاده می‌کند.

## راه‌اندازی آزمایشی

Python 3.10 یا تازه‌تر لازم است. در پوشهٔ پروژه:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

توکن واقعی `TELEGRAM_BOT_TOKEN` و شناسهٔ عددی یک یا چند مدیر را فقط در فایل محیطی امن محیط خود وارد کنید؛ توکن را در چت، کد یا مخزن نگذارید. برای اجرای محلی، متغیرها را در ترمینال صادر کنید. برنامه فایل `.env` را خودکار نمی‌خواند:

```sh
export TELEGRAM_BOT_TOKEN='توکن-واقعی-خودتان'
export ADMIN_IDS='شناسه-عددی-تلگرام-مدیر'
python bot.py
```

توکن را فقط از BotFather بگیرید. شناسهٔ کاربری عددی است، نه نام کاربری. متغیرهای اختیاری در [.env.example](.env.example) آمده‌اند.

## فرمان‌ها

کاربران: `/start`، `/help`، `/rules`، `/newad`، `/myads`، `/search واژه`، `/rankings` و `/cancel`. جست‌وجو دکمه‌های فیلتر واژه، شهر، دسته، نوع و بازهٔ قیمت، پاک‌کردن فیلتر و صفحه‌های بعد/پیش دارد. نشست جست‌وجو در دیتابیس نگهداری و به شناسهٔ همان کاربر محدود می‌شود.

مدیران: `/admin`، `/stats`، `/health`، `/backup`، `/restore_db نام_فایل تأیید`، `/reports`، `/warnings شناسه`، `/modhistory شناسه`، `/warn شناسه دلیل`، `/mute شناسه ثانیه دلیل`، `/unmute شناسه`، `/ban شناسه دلیل`، `/unban شناسه`، `/publish شناسه`، `/retry_publish شناسه بررسی_شد`، `/confirm_published شناسه [شناسهٔ_پیام ...]`، `/category_add نام`، `/category_rename شناسه نام`، `/category_move شناسه جایگاه`، `/rules_set متن` و `/blockphrase عبارت`.

افزودن مدیر فقط با تغییر `ADMIN_IDS` در محیط سرور ممکن است؛ فرمان خودارتقایی وجود ندارد. فرمان‌های محدودسازی تلگرام وقتی کار می‌کنند که `GROUP_ID` و اجازه‌های مناسب ربات تنظیم باشند.

## گروه و نشر آگهی

ربات را به گروه و مقصد نشر اضافه کنید. برای پیام خوش‌آمدگویی، رویداد ورود اعضا را در BotFather خاموش نکنید. برای محدودسازی یا بیرون‌کردن، ربات باید مدیر گروه و دارای اجازهٔ مربوط باشد. نسخهٔ فعلی پیام مشکوک را ثبت و برای بررسی علامت‌گذاری می‌کند؛ خودکار حذف یا محروم نمی‌سازد.

برای نشر، `AD_PUBLICATION_CHAT_ID` را تنظیم کنید و ربات را در مقصد مدیر بسازید. حالت پیش‌فرض `MODERATION_REVIEW_MODE=required` است و پیش از نشر تأیید مدیر لازم دارد. در حالت `auto` آگهی بدون بررسی مدیر برای نشر فرستاده می‌شود؛ فقط پس از سنجش خطر آن را فعال کنید. اگر مقصد تنظیم نباشد، آگهی تأیید می‌شود ولی نشر نمی‌شود.

## نصب روی VPS با systemd

GitHub کد را نگهداری می‌کند، اما ربات را پیوسته روشن نگه نمی‌دارد. اجرای همیشگی به VPS لینوکسی یا میزبانی پیوسته نیاز دارد. پشتیبان خودکار به‌طور پیش‌فرض هر ۲۴ ساعت ساخته می‌شود؛ با `AUTOMATIC_BACKUP_INTERVAL_HOURS=0` خاموش می‌شود. `BACKUP_RETENTION_DAYS` و `CLEANUP_RETENTION_DAYS` مدت نگهداری فایل‌های پشتیبان و نشست‌های موقت را تعیین می‌کنند.

1. Python 3.10+ و بستهٔ `python3-venv` را روی سرور نصب کنید. کاربر سیستمی جدا بسازید و نسخهٔ بررسی‌شدهٔ پروژه را در `/opt/bazaarche` قرار دهید.
2. وابستگی‌ها را در محیط مجازی نصب کنید و مالکیت پروژه را به کاربر سرویس بدهید.
3. `/etc/bazaarche/bot.env` را بسازید و دسترسی‌اش را محدود کنید (`chown root:root` و `chmod 600`). متغیرهای `.env.example` را با تنظیمات خود پُر کنید؛ توکن را در فرمان ترمینال ننویسید.
4. [deploy/bazaarche.service](deploy/bazaarche.service) را به `/etc/systemd/system/` ببرید، مسیرها و کاربر را بازبینی کنید، سپس `systemctl daemon-reload` و `systemctl enable --now bazaarche` را اجرا کنید.
5. وضعیت را با `systemctl status bazaarche` و گزارش را با `journalctl -u bazaarche` ببینید. تنظیم نگهداری [deploy/journald.conf](deploy/journald.conf) را در `/etc/systemd/journald.conf.d/bazaarche.conf` بگذارید و journald را بازراه‌اندازی کنید.

دیتابیس و فایل محیطی باید پایدار و فقط در دسترس کاربر سرویس باشند. نمونهٔ systemd با کاربر غیرریشه، محدودسازی مسیرها، راه‌اندازی دوباره پس از خرابی و خاموشی آرام تنظیم شده است. هم‌زمان فقط **یک** نمونهٔ polling را با یک توکن اجرا کنید؛ اجرای چند نمونه باعث رقابت دریافت updateها می‌شود.

## Railway و Railpack

در [railway.json](railway.json) سازندهٔ `RAILPACK` و فرمان اجرای `python bot.py` مشخص است؛ [`.python-version`](.python-version) نسخهٔ Python را روی 3.12 می‌گذارد. Build command سفارشی تعیین نشده تا Railpack وابستگی‌ها را از `requirements.txt` نصب کند. این برنامه long-polling است و به HTTP port نیاز ندارد؛ آن را به‌عنوان web server یا چند replica اجرا نکنید.

در Railway Variables، `TELEGRAM_BOT_TOKEN` و `ADMIN_IDS` را محرمانه وارد کنید. برای پایداری SQLite یک Railway Volume را به `/data` وصل و `DATABASE_PATH=/data/bazaarche.sqlite3` و `BACKUP_DIRECTORY=/data/backups` تنظیم کنید؛ بدون volume پایدار، فایل دیتابیس ممکن است پس از redeploy از بین برود. مقدارهای متغیر را در کد یا GitHub نگذارید.

Railway CLI، Build Logs و Build واقعی Railway در این محیط موجود نبودند؛ پس این پیکربندی صریح شده اما موفقیت Build در Railway تأیید نشده است. اگر Build باز هم شکست خورد، بخش **Build Logs** مربوط به همان deployment را همراه نام service و زمان اجرا بفرستید؛ پیام Railpack از ابتدا تا نخستین traceback/error برای تشخیص قطعی لازم است. مقدار token را پیش از فرستادن log حذف کنید.

## دیتابیس و پشتیبان

SQLite برای یک میزبان کوچک مناسب است. کلیدهای خارجی، تراکنش‌ها، WAL، نمایه‌ها و نسخه‌بندی طرح‌واره فعال‌اند. SQLite برای چند میزبان یا نوشتن پرتعداد مناسب نیست؛ اگر چند نمونه، صف نوشتن طولانی یا دسترس‌پذیری چندمیزبانه لازم شد، PostgreSQL را در نظر بگیرید. ارتقای طرح‌واره هنگام آغاز برنامه انجام می‌شود؛ پیش از ارتقا پشتیبان بگیرید.

مدیر با `/backup` نسخهٔ آنلاین می‌سازد؛ فایل در `BACKUP_DIRECTORY` با دسترسی محدود ذخیره و برای مدیر فرستاده می‌شود. پشتیبان زمان‌بندی‌شده نیز با lease دیتابیسی از اجراهای تکراری جلوگیری می‌کند و فایل‌های قدیمیِ ساخته‌شده توسط برنامه را پس از مهلت نگهداری پاک می‌سازد. نسخهٔ سروری را جداگانه و رمزگذاری‌شده به محل دیگری انتقال دهید.

برای بازیابی از تلگرام، نام یک فایل معتبر داخل `BACKUP_DIRECTORY` را بگیرید و فرمان `/restore_db bazaarche-زمان.sqlite3 تأیید` را فقط پس از بررسی فایل اجرا کنید. فرمان فقط مدیر را می‌پذیرد، نام فایل را به مسیر همان پوشه محدود می‌کند، سلامت و نسخهٔ طرح‌واره را می‌سنجد و **پیش از هر جایگزینی یک پشتیبان از دیتابیس فعلی می‌سازد**. اگر بررسی یا ساخت پشتیبان پیشین شکست بخورد، جایگزینی آغاز نمی‌شود. پس از بازیابی `/health` را اجرا کنید. برای بازگشت نسخهٔ برنامه، کد قبلی را مستقر کنید؛ اگر طرح‌واره جلو رفته باشد، پشتیبان پیش از ارتقا را بازیابی کنید.

## آزمون و عیب‌یابی

```sh
python -m unittest discover -s tests -v
python -m compileall -q bot.py config.py database.py handlers services tests
```

آزمون‌ها به توکن یا شبکهٔ تلگرام نیاز ندارند. `/health` سلامت SQLite را می‌سنجد. خطای اجازهٔ نشر یا مدیریت گروه را در `journalctl` بررسی کنید؛ پیام عادی کاربر جزئیات استثنا را نمی‌گیرد. برای پیام خصوصی، کاربر باید قبلاً ربات را آغاز کرده باشد.

## وضعیت و محدودیت‌ها

ثبت آگهی چندمرحله‌ای با پیش‌نویس پایدار، اصلاح و تأیید مدیر انجام می‌شود. یک تا ده عکس به شکل آلبوم تلگرام فرستاده می‌شوند و شناسهٔ همهٔ پیام‌ها ذخیره می‌شود. فیلترهای جست‌وجو و صفحه‌بندی، گزارش تکرارنشدنی، امتیاز پس از تأیید، رتبه‌بندی فعالیت هفت روز گذشته، تنظیم خاموش‌کردن رتبه‌بندی عمومی، مدیریت دسته‌ها، انقضا و پشتیبان‌گیری زمان‌بندی‌شده فراهم است. امتیاز گواه اعتماد نیست و پرداخت وجود ندارد.

مدیر دسته را با `/category_add نام` می‌افزاید، با `/category_rename شناسه نام` تغییر نام می‌دهد، با `/category_move شناسه جایگاه` مرتب می‌کند و در پنل دسته‌ها فعال/غیرفعال می‌سازد. برای retry نشر مبهم، مقصد را دستی وارسی کنید و تنها اگر آگهی آن‌جا نیست `/retry_publish شناسه بررسی_شد` را بزنید. اگر پیام‌های عکس از تلگرام رسیده‌اند ولی پاسخ/توضیح کامل نشده، آن‌ها را وارسی و سپس `/confirm_published شناسه شناسهٔ_پیام ...` را اجرا کنید؛ این فرمان چیزی دوباره نمی‌فرستد.

هشدار `python-telegram-bot` دربارهٔ `per_message=False` باقی است: روند آگهی عمداً میان callback دکمه و پیام‌های متنی همان کاربر ادامه می‌یابد؛ فعال‌کردن `per_message=True` این حالت‌ها را به شناسهٔ پیام‌های جدا می‌شکند و روند wizard را خراب می‌کند. بنابراین هشدار بررسی شد و گزینهٔ پیش‌فرض لازم حفظ شده است. محدودیت پیوند هنوز پیام را فقط علامت‌گذاری می‌کند؛ ربات پرداخت یا بررسی زندهٔ اعتبار فروشنده ندارد.

**اتصال زنده به تلگرام، مجوزهای واقعی، نشر در گروه/کانال، اجرا روی VPS و بازیابی عملی از پشتیبان در این محیط آزمایش نشده‌اند.** مدیر باید شناسه‌ها و دسترسی‌های تلگرام را روی سرور خود تنظیم کند؛ توکن یا معلومات سرور را در مخزن نگذارد.
